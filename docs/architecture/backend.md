# Backend Architecture (apps/api)

NestJS, TypeScript, REST (versioned `/api/v1`), WebSocket support delegated
to `apps/realtime`.

## Module anatomy

Every domain module under `src/modules/<name>` follows the same shape
(generated by `infrastructure/scripts/gen-nest-modules.sh`):

```
modules/<name>/
├── controller/<name>.controller.ts   HTTP surface only — no business logic
├── service/<name>.service.ts         Business logic, orchestrates repositories
├── repositories/<name>.repository.ts Tenant-scoped Prisma access ONLY
├── dto/                              class-validator request/response DTOs
├── entities/                         Module-specific response shapes
├── interfaces/                       Module-internal contracts
├── guards/                           Module-specific guards (rare — most auth is global)
└── <name>.module.ts                  Wires the above together
```

**Controllers never touch Prisma.** Only a module's `repositories/*` may
import `DatabaseService`/`scopedPrisma`. This is what makes tenant-scoping
auditable — a `grep` for `prisma\.` or `db\.forTenant` outside
`repositories/` is a code-review red flag.

## Request pipeline (global, in order)

```
Middleware → JwtAuthGuard → TenantGuard → RolesGuard → PermissionsGuard
  → ThrottlerGuard → Pipes (ValidationPipe) → Interceptors (pre)
  → Controller handler → Interceptors (post: Response envelope, Logging)
  → (on throw) HttpExceptionFilter
```

Registered once in `app.module.ts` via `APP_GUARD`/`APP_FILTER`/
`APP_INTERCEPTOR` — no controller opts out except via `@Public()`
(`packages/auth`). See [authentication.md](./authentication.md) and
[authorization.md](./authorization.md) for what each guard does.

## infrastructure/ vs modules/

`infrastructure/{database,redis,storage,email,queue}` are global NestJS
modules wrapping cross-cutting concerns (`packages/database`,
`packages/storage`, BullMQ, ioredis, outbound email). They are infrastructure
**providers**, not business modules — nothing here has an `organisationId`
concept baked in beyond `DatabaseService.forTenant()`.

`modules/*` are the 32 business domains listed in the database ERD
(candidates, jobs, applications, placements, ...). Both layers are modules
in the NestJS sense; the split exists so `import` paths make the
distinction between "generic platform capability" and "recruitment
business logic" visible at a glance.

## Background work

Anything slow or unreliable (sending email, parsing a CV, generating a
report, bulk import/export, scheduled reminders) is enqueued via
`infrastructure/queue` (`@InjectQueue(QUEUE_NAMES.X)`) and processed by
`apps/worker`, never executed inline in a request handler. Queue names are
defined once in `@crm/config` so producer (api) and consumer (worker) can't
drift.

## File uploads

Controllers never write file bytes to Postgres. The flow is:
`CandidateDocument`/`Document` metadata row → Postgres;
actual bytes → `StorageProvider` (`packages/storage`, S3-compatible: AWS S3
/ Cloudflare R2 / MinIO — see `.env.example` `STORAGE_*`). MIME type and
size are validated against `ALLOWED_UPLOAD_MIME_TYPES` /
`STORAGE_MAX_UPLOAD_MB` before a signed upload URL is issued.
